# AGENTS.md - PiuReconstructed

C recompilation ("recomp") of **Pump It Up (DOS build of 12/18/2000)**: `game/PIU.EXE` (Watcom LE/DOS4GW, Glide2x). The goal is to reproduce the screens and behavior **exactly like the original** (fidelity first). Reply in Portuguese (BR).

## Where to look for the truth (in order)
1. **`game/PIU.EXE`** - primary source. Open it with REA/Ghidra through the synthetic PE `piu_le.exe` (generated by `tools/le_to_pe.py`; addresses = DOS VAs, e.g. `FUN_0002C840`). Watcom calling convention: arguments in EAX/EDX/EBX do not show in the pseudocode, read the **assembly**.
2. **If it is not in PIU.EXE, look in `game/piu` (Linux ELF, R5/v3.52)**. It is not stripped: the `func_XXXXX` / `jump_XXXXX` / `vtable_XXXXX` symbols use **the same hexadecimal address as the DOS function** (e.g. `func_2c840` = `FUN_0002C840`), so it works as an address translator and a second opinion. It holds tables and codes that the DOS decompilation hides.
   - REA's Ghidra on Windows **does not open ELF**. Use `nm`, `readelf` and `objdump -d -M intel --no-show-raw-insn piu` (MinGW) and Python to read tables: convert virtual address to offset using the program headers.
   - The ELF data lives at other addresses (e.g. mode flags = `0x81206d2`; in DOS `DAT_0012B028`); find them through the equivalent code.
   - Caveat: the ELF **key** tables (`player1keys`...) are the port's mapping, not the DOS pad bits.
3. `game/STAGE.CFG`, `game/*.DAT` (`tools/piu_res.py`, `tools/piu_bga.py`) and `game/EFFECTS/*.wav` for data.
4. User observation (while playing) counts as proof of behavior; record it as "empirical".

Example of an ELF-only finding: secret codes REMIXDB / REMIXCZ (`func_2a72b`, table `0x81219AA`) - see `docs/FUNCTION_MAP.md` (Update 27).

## Working rules
- Distinguish **confirmed** (read in code/data) from **inferred**; mark inferences in comments and in the docs.
- "Disabling" code = wrap it in `/* */`. Do not refactor without being asked.
- **Each change = 1 commit**; new scene = +0.1.0 version (tag `v0.N.0`; current v0.9.0). The message ends with the `Co-Authored-By` line defined by the environment.
- Document every discovery in `docs/FUNCTION_MAP.md` ("Update N" section).
- Test: `build_msvc` (CMake/MSVC Release) produces `piu.exe`; copy it to `game/PIUTESTE.EXE` (if "in use", `PIUTESTE_NOVO.EXE`). Captures: `-shot f.ppm -selftest SEG`, shortcuts `-mode N`, `-conf N`, `-wheel N -wdir D`, `-service N`.
- Input: P1 `Z Q S E C` (bits 1/2 blue Z/C = scroll, 8/0x10 Q/E = point, S = center), P2 numpad `1 7 5 9 3`; F1 service, F2 test, F3 coin clear, F4 coin; 1-8 speed.
- **Documentation in 3 languages**: every `.md` has pt-BR (`X.md`, original), English (`X.en.md`) and Spanish (`X.es.md`) versions, with the language line at the top. When editing one, update all three in the same commit.
- REA sessions: `open_binary` on a single target at a time; if you get `cleanup_incomplete`, run `close_binary` and open again.
